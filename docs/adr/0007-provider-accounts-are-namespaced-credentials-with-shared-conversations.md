# Provider Accounts Are Namespaced Credentials With Shared Conversations

Convergence needs to run several Claude Code subscription accounts on one machine (MAR-2199), selectable per turn so a session can continue on a fresh account when the current one nears its limit. Claude Code stores subscription OAuth in the macOS Keychain rather than a file, under service `Claude Code-credentials` suffixed with the first eight hex characters of `sha256(NFC(dir))`, where `dir` comes from `CLAUDE_SECURESTORAGE_CONFIG_DIR` when set and otherwise from the resolved config directory. The suffix is applied on the _presence_ of either variable, not its value: exporting `CLAUDE_CONFIG_DIR=~/.claude` produces a hashed slot even though the directory is unchanged. Convergence will give each account its own `CLAUDE_CONFIG_DIR` with `projects/` symlinked into the shared conversation store, and pin `CLAUDE_SECURESTORAGE_CONFIG_DIR` to a separate stable per-account path.

Credential-only isolation — one shared config directory, per-account credential namespace — was the first candidate and is rejected. It supports hot-swapping, but all accounts then share `~/.claude.json`, which is last-writer-wins and carries behavioural state rather than only display metadata: `modelAccessCache`, `orgModelDefaultCache`, and tier and availability gating. Accounts on the same subscription tier are not automatically safe, because they belong to different organizations and organizations differ in model rollouts, beta access and defaults. Fully per-account config directories were the second candidate and are also rejected on their own: they are correct on every isolation axis but partition `projects/`, so resuming a conversation under a different account fails with `No conversation found with session ID`, and they partition global skills, which contradicts the requirement that an account supply only credentials. Migrating transcripts between accounts on each swap was considered and rejected as a primary mechanism, because transcripts embed absolute paths and carry tool-result sidecars, subagent state, file history and checkpoints. The chosen combination is the only one that isolates organization-scoped caches while keeping conversations resumable across accounts.

The account directory path is part of the Keychain service name, so it is a correctness constraint rather than a layout preference. It must derive from a hardcoded constant such as `~/.convergence/provider-accounts/claude/<uuid>` and never from `app.getPath('userData')`: `package.json` names the app `convergence` while electron-builder sets `productName: Convergence`, and although those resolve to the same folder on a case-insensitive filesystem they hash to different slots, so accounts enrolled under `npm run dev` would be invisible to the installed build. Pinning the credential namespace to a path distinct from the config directory keeps credential identity stable if the configuration layout is later restructured.

Child process environments are built from an allowlist rather than by copying `process.env` and removing known credential variables. Documented authentication precedence places `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `apiKeyHelper` and `CLAUDE_CODE_OAUTH_TOKEN` above subscription OAuth, so any inherited credential silently outranks the selected account; a blocklist can only enumerate the variables that exist today, and a future release that adds one would regress account selection without any visible failure. The allowlist is applied after settings resolution, because shared `settings.json` can itself inject environment variables at startup.

Account identity is captured once at enrolment from the account directory's own `.claude.json` and stored in Convergence's database. `claude auth status` is not used at runtime: under a shared configuration directory it reports the identity of whichever account logged in last, independent of the credential actually in use. Accounts are removed by running `claude auth logout` with the account's credential namespace and a throwaway `CLAUDE_CONFIG_DIR`, which deletes only that Keychain slot and leaves the shared profile untouched; deleting the Keychain entry directly would duplicate an undocumented naming function and would not port off macOS.

`CLAUDE_SECURESTORAGE_CONFIG_DIR` is absent from Anthropic's published environment-variable reference. It works in 2.1.220 and an invalid namespaced credential fails closed rather than falling back to the default account, but neither property is guaranteed across releases. Convergence therefore attests identity fail-closed whenever the Claude binary version changes and periodically thereafter, comparing the enrolled identity against the account directory's current record and disabling the account on mismatch, which also detects a future release that ignores the variable and quietly serves the default account. The documented `claude setup-token` mechanism is retained as a degraded fallback — one-year, non-refreshing, model-requests-only, and requiring Convergence to custody a long-lived secret — and must not become the default path.

Because Convergence spawns a fresh provider process per turn and rejoins conversations with `--resume`, account selection needs no process lifecycle management, and switching accounts mid-conversation is a property of the existing design rather than a new capability. The account is not pinned at session start. It is recorded per turn instead: on every queued input and on every `session_turn`, held immutable for the whole logical turn including deferred-tool and recovery continuations, with the session-level selection treated as composer state only. Claude's transcripts record no account attribution, so if Convergence does not persist it the information does not exist. Accounts are scoped to an execution host; remote sessions fail closed until the wire protocol carries host-scoped, non-secret account references.
